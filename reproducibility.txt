RecoverML reproduction guide
Updated 16 October 2026

This guide starts with a fresh Linux or Windows laptop and explains installation
and saved-data checks and fresh experiments and the exact recovery boundary
Run commands from the repository root unless a step says otherwise
Commands labelled PowerShell run in Windows and other commands run in Ubuntu
The paper draft and PDF are preserved while the author reviews the results

1 CHOOSE THE CHECK YOU WANT

A Saved evidence audit
Check supplied file identities and regenerate figures/tables from recorded logs
This checks the analysis and does not create new execution measurements

B Fresh capture and recovery
Capture new histories in your own environment and restore their own exact bytes
This is the main route for a laptop or second-environment reproduction

C Original archived store replay
Restore the old captured outputs from an old selected store in its fully matching
recorded environment and source implementation
Python patch versions and numerical library paths and BLAS identities matter
Matching only the eight direct package versions is not enough
An environment/source rejection means that archived replay did not pass
Do not disable the guard to make an old capture replay in a different environment

The guarantee assumes intact retained files and the recorded supported operators
and only the declared allowed capability losses
It does not promise that retraining on every CPU produces the same old bytes
It does not promise recovery from corruption or deletion of mandatory retained data
The checks detect such conditions and refuse unsafe recovery

3 COMPUTER AND OPERATING SYSTEM

Use a Linux CPU computer or Ubuntu through WSL2 on Windows
A GPU is not needed for the current planners and CPU forests and benchmark grids
The recorded local host had an eight CPU quota and an eight GiB memory limit
Those are recorded values and not a measured minimum hardware specification
Allow enough disk space for captured models and native DVC caches and archives
The larger study can create multiple GB of real temporary data
The exact duration and peak disk/RAM needs depend on the machine
Start with the smoke test before running long studies

Use Python 3.12
Fresh experiments accept Python >=3.12 and <3.13
Original captures record Python 3.12.14 and the fresh cloud run records 3.12.15
Do not change the package range merely to use Python 3.11 or 3.13

Linux supplies Bash and /proc resource readings used by the full runners
Windows users do not need to replace Windows or buy another computer
WSL2 runs Ubuntu on the existing laptop
Keep the repository and timing outputs in the Linux filesystem rather than /mnt/c
because a mounted Windows filesystem changes I/O behavior
A personal laptop is a valid additional reproduction environment
A second environment is not a distributed scale-out benchmark or external review

If WSL2 is already installed skip to section 4
Otherwise open PowerShell as Administrator

PowerShell:
    wsl --list --online
    wsl --install -d Ubuntu-24.04

Use the listed distribution name if it differs
Restart if requested then open Ubuntu and create its user account

PowerShell:
    wsl --list --verbose
    wsl --set-version Ubuntu-24.04 2

The last command is needed only if that Ubuntu installation is not already WSL2

7 VERIFY THE SUPPLIED FILES BEFORE EDITING THEM

Use a new output path. --require-complete intentionally fails until the
missing historical artifacts are supplied and match their recorded hashes.

    python scripts/recheck_published_ledgers.py --output work/new_ledger_recheck

This performs metadata/structural analysis and six ledger corruption controls.
It does not replay models, rerun DVC, or verify an absent frontier archive.
The earlier direct-file check below additionally detects working-copy changes;
Windows CRLF conversion can cause a mismatch even when Git bytes are correct.

    python - <<'PY'
import hashlib
import json
from pathlib import Path
manifest_path = Path('CHECKSUMS_GITHUB.json')
manifest = json.loads(manifest_path.read_text())
errors = []
for name, expected in manifest.items():
    path = Path(name)
    if not path.is_file():
        errors.append('Missing: ' + name)
    elif hashlib.sha256(path.read_bytes()).hexdigest() != expected:
        errors.append('Changed: ' + name)
if errors:
    raise SystemExit('\n'.join(errors))
print('Verified', len(manifest), 'listed files')
PY

A checksum verifies identity and does not itself prove an experiment correct
The checksum manifests exclude themselves to avoid circular identities
Result reports and publication receipts add their own source and raw-output hashes

16 READ RESULTS CORRECTLY AND SAVE COMPLETED WORK

Read report.json and analysis.json and summary.csv and their raw trace identities
Check the exact request and expected blocked and unexpected failure denominators
All methods within a case must see the same graph and requests and admitted budget
Actual retained bytes matter as well as the maximum allowed bytes
A heuristic above budget is not admissible and a heuristic below full coverage
cannot be compared with a fully robust store as if it met the same guarantee

The independent unit is the history or appropriately grouped dataset/seed block
Versions and fault combinations and policy repeats are correlated conditions
One recovery trial per request does not estimate a stable tail distribution
Do not compare a server time with a laptop time as a paired speedup
Process peak RSS is a process high-water mark and /proc I/O reflects the page cache
Kernel microbenchmarks do not establish whole-system recovery speedup
Snapshots can restore faster and broad failure scopes can legitimately save zero

17 COMMON PROBLEMS

Python 3.12 is unavailable
Use Ubuntu 24.04 or a supported Python 3.12 installation and recreate the environment
Do not silently change package/runtime versions for an exact old replay

recoverml is not found
Activate .venv and run python -m pip install -e '.[paper]' in the repository root

A required package is missing
Install requirements.txt in the active environment and repeat section 5's version test

HYPPO/STARE download fails
Keep the log and check access to GitHub/raw.githubusercontent.com
The pins and hashes must match and an inaccessible download is not a passed check
Do not invent or substitute a source revision

Source or environment identity mismatch
Preserve the rejection and use fresh captures in your own environment
Do not disable the identity check

Existing output directory
Use a new destination and keep the incomplete attempt
Do not merge summaries while losing raw-request identities or timing evidence

Missing raw records despite advancing summaries
Stop safely and preserve the attempt and move new streams to a unique /tmp path
Reuse only fully reconciled capture/case boundaries under a documented rule
Never reconstruct lost timings from aggregates

Memory/disk pressure or solver timeout
Record the failure and save complete existing evidence
Changed settings require a separately labelled protocol/run
A timeout is an unknown optimization result and is not proof of infeasibility

No display for plots
Use MPLBACKEND=Agg and open the produced PNGs separately

Native Windows resource failures
Use Linux or WSL2 for Bash and /proc monitoring
