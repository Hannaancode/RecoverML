RecoverML reproduction guide
Updated 14 October 2026

Read this guide from start to finish before running a long experiment
Commands marked PowerShell run in Windows and all other commands run in Ubuntu
Run the Ubuntu commands from the repository root unless stated otherwise
The paper formatting will be revised after the author has reviewed the draft

Current publication availability
The source and guide and summaries and figures can be published separately
Some compressed raw logs and selected model/data store archives are still awaiting
public upload approval and are preserved in the author's complete local package
The exact filenames and hashes are in docs/PUBLICATION_PENDING_OCT14.json
Fresh experiments create their own logs and stores and do not require these saved archives
Saved-data figure audits and archived store replay need the complete saved evidence
Do not report those checks as completed from a clone that lacks the listed inputs

1 WHAT THIS GUIDE REPRODUCES

There are three different checks

A Saved evidence check
Verify the supplied files and regenerate the nine current paper plots and
their claim tables from saved measurements
This verifies the analysis and does not create new benchmark measurements

B Fresh experiment run
Capture new histories and run the planners and recovery requests in your own
installed environment and write new measurements in a new results folder
This is the main route for checking the project on another computer

C Archived store replay
Recover original captured targets from a saved selected store with its
recorded source and exact environment checks
The current guard compares the whole recorded environment including Python
patch version and numerical library paths and BLAS details
Matching only the main package versions is not sufficient for this route
An environment rejection on a fresh laptop is expected when those fields differ
Do not disable the guard or claim that a rejected replay passed
Use route B to test fresh capture and exact recovery on that laptop

The exact promise concerns intact retained files and recorded operators and
the declared allowed capability losses in the supported recorded environment
It does not promise that training on every CPU produces the same bytes
It does not simulate arbitrary disk corruption or a complete operating system loss

2 COMPUTER AND SOFTWARE NEEDED

Use a Linux CPU computer or Ubuntu through WSL2 on Windows
A GPU is not needed for the current complete paper matrix
The recorded host used an eight CPU quota and an eight GiB memory limit
Those are recorded measurements rather than a measured minimum requirement
Allow free disk space for this repository and newly captured stores and logs
The complete matrix needs much more space and time than the smoke check
Exact duration depends on the computer and solver and no fixed duration is promised

Use Python 3.12
The original final captures record Python 3.12.14
The project accepts Python >=3.12 and <3.13 for fresh experiments
Python 3.11 and 3.13 are outside this package's declared range

Internet is needed for initial package installation and the pinned HYPPO download
Optional earlier text experiments also download the public 20 Newsgroups data
The current matrix uses the included Banknote data and scikit-learn datasets

3 WINDOWS SETUP

If Ubuntu with WSL2 is already installed open it and go to section 4
Otherwise open PowerShell as Administrator

PowerShell:
    wsl --list --online

Choose Ubuntu-24.04 if that name is listed because it supplies Python 3.12

PowerShell:
    wsl --install -d Ubuntu-24.04

Restart if requested and open Ubuntu and create your Linux user account
Check the version from PowerShell

PowerShell:
    wsl --list --verbose

The Ubuntu entry should show version 2
If the installed distribution has another name use its exact name

PowerShell:
    wsl --set-version Ubuntu-24.04 2

Keep the project in the Linux home folder for the timing runs
Avoid running the storage benchmark from a mounted Windows folder such as /mnt/c
That filesystem choice can change I/O timings
WSL uses your laptop hardware and does not require replacing Windows

Official installation instructions:
https://learn.microsoft.com/en-us/windows/wsl/install

5 CREATE AN ISOLATED PYTHON ENVIRONMENT

    python3.12 --version
    python3.12 -m venv .venv
    source .venv/bin/activate
    python -m pip install --upgrade pip
    python -m pip install -r requirements.txt
    python -m pip install -e '.[paper]'
    python -m pip check

requirements.txt pins the seven direct packages used by the complete CPU paper run
The five core packages and the two paper packages match pyproject.toml
Transitive packages are resolved by pip and are recorded with pip freeze below
The editable installation makes the recoverml command available
Always use python -m pip so installation targets the active Python interpreter

Check the required packages

    python - <<'PY'
import importlib.metadata

expected = {

    export OMP_NUM_THREADS=1

6 MAKE A NEW REVIEW FOLDER AND RECORD THE MACHINE

Use a unique name each time and leave the original evidence unchanged
The following command creates a UTC timestamped folder

    review_out="results/runs/review_$(date -u +%Y%m%dT%H%M%SZ)"
    mkdir -p "$review_out"
    git rev-parse HEAD > "$review_out/commit.txt"
    python --version > "$review_out/python.txt"
    python -m pip freeze > "$review_out/packages.txt"
    uname -a > "$review_out/linux.txt"
    lscpu > "$review_out/cpu.txt"
    free -h > "$review_out/memory.txt"
    python - <<'PY' > "$review_out/environment.json"
import json
from recoverml.core import environment
print(json.dumps(environment(), indent=2))
PY

For a ZIP without Git metadata omit only the git rev-parse command
Record that the input was the ZIP and keep the verified checksum list
Use the actual measured hardware details rather than copying our server details

7 VERIFY THE SUPPLIED FILES

Run this before making changes to tracked files
For a GitHub clone use CHECKSUMS_GITHUB.json in the command below
For the complete local package replace that name with CHECKSUMS.json
The GitHub manifest covers the published subset while the complete manifest
also covers the local evidence files whose public upload is awaiting approval

    python - <<'PY'
import hashlib
import json
from pathlib import Path
manifest = json.loads(Path('CHECKSUMS_GITHUB.json').read_text())
errors = []
for name, expected in manifest.items():
    path = Path(name)
    if not path.is_file():
        errors.append('Missing: ' + name)
    elif hashlib.sha256(path.read_bytes()).hexdigest() != expected:
        errors.append('Changed: ' + name)
if errors:
    raise SystemExit('\n'.join(errors))
print('Verified', len(manifest), 'supplied files')
PY

CHECKSUMS.json excludes itself to avoid a circular checksum
CHECKSUMS_GITHUB.json excludes itself and the complete manifest to avoid a circular checksum
The saved evidence inventory and claim ledgers provide additional result hashes
A checksum verifies file identity and does not by itself prove experiment correctness

12 RUN THE COMPLETE FRESH MILESTONE 2 PERFORMANCE MATRIX

    bash run_benchmarks.sh "$review_out/fresh_milestone2"

The script runs the correctness suite and smoke storage benchmark and audit
and the three-policy performance matrix at two scales and 1 and 2 and 4 workers
with three trials per condition

It refuses an already existing destination
Use a new folder for a retry rather than replacing original logs

13 RUN THE COMPLETE FRESH CURRENT PAPER MATRIX

Check that section 5 installed DVC and NetworkX before this step
The pinned original HYPPO file is downloaded and hash checked automatically
The original third-party source is not redistributed as our project code

    set -o pipefail
    bash scripts/run_paper_benchmarks.sh "$review_out/fresh_paper" 2>&1 | tee "$review_out/paper_runner.log"

The script runs the following suites in order

    tabular       Four datasets and three seeds and twelve versions and two loss bounds
    estimators    Real Digits forest and canonical neural inference artifacts
    scaling       Two exact planners against analytic storage minima
    index         Indexed certificate recovery against the recorded scan implementation
    dvc           Native DVC add and historical checkout with target hash checks
    merged        A shared graph with multiple real historical branches
    holdout       New topology settings reserved for engine selector checks
    auto_real     The engine selector on the newly created merged graph
    components    Exact physical reduction and layered AND dependency controls
    published     HYPPO components and HELIX rule sensitivity controls at common budgets
    fault_scope   Preprocessing and fitting and prediction capability loss controls
    analysis      The five initial figures and their tables and claim ledger
    extension_analysis  The four final figures and verified comparison tables

The runner uses built-in default settings matching the declared paper matrix
Each suite records its own actual measurements and source and environment
The HYPPO file is pinned to revision
    405e42de863272fcb71a625cf6b2ae0696c7a8c5
and SHA-256
    b857a387b81127585cb19a5925f1b1a84ed63361db5184ea3c84f8adc864765a

The HELIX comparator is our documented published rule implementation
The HYPPO comparator runs unchanged released materialization functions with
the disclosed graph adapter
These are decision rule comparisons through a shared recovery executor
They do not measure full native HELIX or HYPPO system performance

DVC runs its native snapshot commands and its metadata accounting is separate
from the common normalized payload storage measure
Capability failures are injected replay call restrictions rather than package
uninstallation and retained files remain intact

If a suite fails the shell exits and the earlier completed suites remain saved
Keep the failure log and use a new destination for a corrected rerun
Do not describe a partial matrix as a completed full run

Read report.json and summary.csv and the claim ledger in each new suite
The saved paper evidence is results/research/paper_oct14
Important saved counts include

    tabular      48 cases and 28512 requests across the compared policies
    estimators   8 cases and 1584 requests across the compared policies
    published    56 cases and 33440 requests across ten policies
    fault_scope  36 scope/bound cases and 3920 exact requests across two exact methods
    merged       112 protected versions and 2464 exact requests across two exact methods
    components   118 planning runs and 9288 exact disk requests
    dvc          40 actual historical snapshot checkouts

The saved published comparison has 3344 requests for each policy
    RecoverML decomposed   3344 exact
    HYPPO rank             2240 exact
    HYPPO frequency        2291 exact
    Best tested common budget HELIX setting   1940 exact

These are the saved measurements and are not promised outcomes on every new capture
Capture times can affect cost-based comparator decisions and a new machine can
change numerical bytes and alias opportunities even with the same dataset seeds
For a fixed recorded graph the certified exact methods should agree on the
minimum retained bytes and every protected request should match its own capture
Store all deviations and explain them instead of editing measurements to match

Timing differences across CPUs and filesystems are expected
Compare relative behavior and repeated trial distributions within each machine
Do not compare an old server time with one new laptop time as a paired speedup
The index result is a certificate kernel measurement rather than whole-system speed
The current source guard also restricts direct replay of old captures as below

18 COMMON PROBLEMS

python3.12 command not found
Use a Linux distribution that supplies Python 3.12 or install Python 3.12 using
the official Python build instructions and then recreate the virtual environment
Do not change the package range merely to install on Python 3.13

ModuleNotFoundError for recoverml
Activate .venv and run python -m pip install -e '.[paper]' from the repository root

Missing networkx or dvc
Install requirements.txt in the active environment and repeat the version check

Execution environment/operator code mismatch
This is the strict archived capture guard described in sections 1 and 16
Use a fresh capture for the laptop check and preserve the rejection log

HYPPO download fails
Check access to raw.githubusercontent.com and keep the failed request log
The pinned source must pass its recorded SHA-256 before the comparator runs

Choose a new output folder or FileExistsError
Use a new output destination and preserve earlier evidence

Plots fail to open on a terminal-only machine
Set MPLBACKEND=Agg and open the saved PNGs using your usual image viewer

Memory pressure or a long solver run
Keep other large programs closed and begin with the smoke check
Record any changed experiment settings and do not combine that run with the
unchanged full matrix as if the settings were identical

Resource tracing requires Linux /proc
Run the complete performance benchmark in Linux or WSL2 rather than native PowerShell

19 WHAT TO SAVE FROM A LAPTOP RUN

Save the exact repository commit and machine details and Python version and
pip freeze and source environment and the test log and runner stdout/stderr
and all raw request and operation and planning logs and regenerated tables and plots
Keep successes and expected blocked requests and unexpected failures
Record whether this was a saved evidence audit or fresh run or archived replay

The results/runs folder is intentionally excluded from Git to keep unfinished
local runs separate from selected paper evidence
Before publishing a new experiment audit it and archive the selected complete
results under a clearly dated results/research folder and record their hashes
Do not commit the virtual environment or downloaded third-party source cache

20 WHEN THE REPRODUCTION CHECK IS COMPLETE

The installation and tests must pass and the chosen fresh run must finish
Its exact methods must agree on the fixed graph objective and protected outputs
must match their own captured bytes and the analysis must audit the saved traces
Record timing changes and explain any changed capture identities or baseline choices

A successful laptop run is evidence from another physical machine
It is not automatically an independent reviewer validation because the author
is still involved and another researcher's run would be a separate check
The current package records one-host experiments and does not claim that this
second-machine check has already happened
