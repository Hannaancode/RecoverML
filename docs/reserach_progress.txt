CURRENT IDEA AND SETUP
RecoverML captures an offline dependency graph for historical ML pipelines
It shares identical serialized artifacts and chooses retained files under a byte budget
It restores requested models and prediction arrays by loading or replaying supported steps
Loaded and rebuilt artifacts must match their original canonical SHA-256 identities
Original source inputs are mandatory and metadata counts toward the budget
Planning starts from a complete capture archive and restoration cannot read that archive
The prototype does not yet provide online admission or crash safe store replacement
Supported models are scikit-learn logistic regression and random forests
Python 3.12 and pinned numpy 2.3.5 scipy 1.17.0 sklearn 1.8.0 matplotlib 3.10.8
The environment and operator code identities are checked during restoration
Capture and planning and restore measurements have separately described scopes
The page cache is warm and each request gets fresh restore state

DATA USED BEFORE TODAY
Seeded synthetic binary classification with 2000 or 10000 records and 20 features
Wisconsin diagnostic breast cancer with its native 569 records
Five historical versions with parameter edits or contiguous one percent data edits
Repeatable steps and a simulated external enrichment response with unavailable random state
The opaque proxy is not an assertion that seeded sklearn training cannot be repeated
Four branch cases share preprocessing and some cases also request an intermediate matrix

LITERATURE UPDATE
The primary HELIX paper says iterative ML can be represented as a DAG and that reuse planning and materialization are different optimization problems
It reports that materialization is NP hard and uses heuristics and selective caching
This directly overlaps with our graph and cost based retention design
The LIMA paper studies fine grained lineage and reuse in ML systems and includes exact and approximate reuse and cache eviction
This overlaps with our content addressed artifacts and dependency recording
Kishu provides incremental checkpoint and checkout for time travel across notebook states
This overlaps with our time travel goal but Kishu focuses on notebook state and our prototype focuses on explicit ML artifacts and replay contracts
These papers mean our current implementation is best described as an auditable course prototype and engineering combination
The narrower possible contribution is a tested policy for mixed replayable and non replayable ML boundaries with all protected targets and exact artifact certificates
That claim still needs a stronger baseline study and varied workloads before it can be called novel

PLANNER VERSION 3 ABLATION — completed 9 October
The ablation selected the 30 opaque cases that invoked the global solver and repeated every version 2 and version 3 pair 30 times
It contains 900 raw paired timing trials across nine opaque captured histories
The execution order alternated so one planner was not always measured first
All 900 pairs produced the same status and exactly the same retained artifacts
Version 3 reduced the solver formulation from 129 variables to 98 which is a 24.0 percent reduction
The median raw planning time was 3.500 milliseconds for version 2 and 2.865 milliseconds for version 3
The median history level speedup was 1.18 times and the bootstrap 95 percent interval was 1.07 to 1.20 times
Version 3 was faster on all nine history level comparisons
The one sided paired Wilcoxon result was p equals 0.001953125 at the history level
This is a statistically clear local machine result and it should still be repeated on another machine before making a broad systems claim

CURRENT RESULT AFTER EXPERIMENT 2
